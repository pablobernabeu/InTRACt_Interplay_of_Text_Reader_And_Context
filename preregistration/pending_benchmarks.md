# Pending benchmark values

This register lists every value in the Stage 1 protocol that a benchmark run before submission will settle. The protocol states each registered rule in full, but some of the figures beside those rules are provisional. They come from public gold and public stories, and a few are expected values that no run has produced yet. None was computed on a story text, and none will be, before in-principle acceptance. Some of the benchmarks' design values, such as the length of their texts, come from counts made on the story texts, which the protocol summarises under Data provenance and lists in Supplementary Section S7.

Each provisional value carries a comment with its identifier, `<!-- PENDING: Pnn -->` in the Markdown and Quarto files, so that a search for `PENDING` finds every one. An identifier can mark more than one place when the same figure appears in several. When a benchmark has run, its final value replaces the provisional text, the comment is deleted and the row below is removed. A value that the benchmark changes is carried into every place that quotes it, and `tools/check_citations.py` and `preregistration/check_reported_numbers.R` are re-run.

The pre-submission benchmarks in the feature plan's schedule (version 3 of 22 October 2026, revised on 3 November) settle these values. Weeks 1 and 2 run from 26 October to 8 November 2026, weeks 3 and 4 from 9 to 22 November, and weeks 5 and 6 from 23 November to 6 December. The work planned for weeks 1 and 2 is running about a week late and should finish around 13 November, in week 3. The Week column gives the week in which each value is now expected to settle, and where it names two stages, the first gives an interim value and the second the final one. Values taken from the error model stay interim until its last run in week 5. That run waits for the subordination count to take direct speech from the registered dialogue detector, for ReferentialContinuity's calibration rule and for the one-factor planning weights from the translated benchmark. It also needs the OpenSubtitles lists, the added languages and the choice of Portuguese parser package (P85).

A checkpoint on Friday 20 November decides whether scope is cut. If the error-model and translated-benchmark outputs for the delivered languages, or the dry run's smoke run (P86), are still missing, the items the plan's short path defers move to after acceptance and before linkage. Rules registered in the protocol then govern them, and they include the bf16 check, the MECO check, the name rule and the TED2020 deposit. Submission is still planned for the week of 14 December 2026, after the author's review from 7 to 13 December, but that date is at risk.
