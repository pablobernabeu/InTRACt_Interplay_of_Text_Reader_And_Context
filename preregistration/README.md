# InTRACt Stage 1 Registered Report

`preregistration.qmd` is the protocol and `supplementary.qmd` the supplementary material.
Both render to PDF and HTML with Quarto and cite `InTRACt references.bib` in APA 7 style
through `layout/apa7.csl`. `layout/nature.csl` is kept beside it for the numbered-superscript
variant Nature Human Behaviour uses at Stage 2, and `layout/breakable-code.lua` lets long inline
code, such as a file path, break across lines in the PDF. The protocol follows the journal's Stage 1 template
section by section (`journal.json` records the limits and the date they were read). The
hypotheses therefore sit inside the Introduction with no subheadings, the Design Table is Table 1 with
the template's five columns, and there is no Discussion or Conclusion. The supplement labels its
display items through Quarto's `crossref` options, so a caption there must not repeat the
"Supplementary Table" prefix by hand. The protocol carries no author block: the Stage 1
submission is anonymised, so the YAML header holds the title alone. `layout/title.tex` is a Quarto
title partial kept for the de-anonymised version, where it prints the numbered affiliations and
the corresponding author's email from a YAML author block, which Quarto's stock PDF template
drops. To use it, restore the author block and list the partial under `template-partials`. Its
`\setstretch` call compiles only because `preregistration.qmd` sets `linestretch`, which makes
Quarto load the setspace package, so that key must stay even at its value of 1.
`cover_letter.md` is the Stage 1 cover letter.

```bash
quarto render
```

Run from this directory, `quarto render` renders both documents listed in `_quarto.yml`.
Its post-render hook, `_rename-output.R`, then renames the protocol's PDF and HTML to
`InTRACt preregistration draft - YYYY-MM-DD`, dated by the render machine's clock, so a
second render on the same day replaces that day's draft. The hook stops with an error if the
dated file is locked, for example open in a PDF viewer. The supplement's outputs keep their
names and are overwritten. Rendering one file, as in `quarto render preregistration.qmd`,
leaves the other document's outputs as they were.

Every dated draft is kept, by the author's decision, as the record of what each version of the
protocol said. The current draft is the one in this folder, and `drafts/` holds the earlier
ones. Once the hook has written a new draft, it moves the one that draft supersedes into
`drafts/`, first copying the Quarto libraries its HTML loads into
`drafts/preregistration_files/`. It never overwrites a file already in `drafts/`, and stops
instead. The PDFs are the faithful record: an HTML draft names its figures by paths relative to
where it was rendered, so `drafts/README.md` explains why its figures do not show there.

Every artefact the protocol describes is generated by one of the scripts below, and the
section on checking the manuscript explains how the numbers quoted in the text are compared
with those artefacts. Run each script from this directory.

## Requirements

The committed outputs were produced with R 4.6.1 (see `design_analysis/session_info.txt`).
`renv.lock` pins every R package the scripts use, at the versions installed, with the
repository each comes from. It takes pilotr 0.3.0, theoryforge 0.6.0, depictr 0.3.0 and
scopusflow 0.4.0 from CRAN, whose releases match the local builds that produced the committed
outputs in every function the scripts call. To build that environment in a separate library,
leaving your own untouched:

```bash
Rscript -e 'renv::restore(lockfile = "renv.lock", library = "renv-library", prompt = FALSE)'
export R_LIBS=renv-library   # then run the steps below as written
```

pilotr fits every simulated replicate with lme4, which it lists only as a suggested package, so
the two simulation scripts check for lme4 by name and the lockfile includes it. On 17 October
2026, a library restored this way reproduced every table, figure and theory output of the steps
below that does not need the Scopus API or a fresh simulation, and both checks passed. The
fresh-simulation paths were run at two replicates per grid point, and the Scopus step with its
API calls replaced by the archived counts, which it reproduced apart from the run date. The R scripts follow `../.lintr.R`, and `Rscript -e 'lintr::lint_dir()'` reports
no lints. The 2026-10-16 draft was rendered with Quarto 1.10.19 and LuaTeX 1.24.0 (TeX Live
2026). The count script and the two story-text scripts need Python 3.8
or later and nothing outside the standard library. Regenerating the framework figure in
`../mindmap/source` needs Node.js and network access.

ordinal run at 3,200 texts exhausted memory, which is why that point is
absent from the default grid.

## Checking the manuscript against its artefacts

After regenerating any artefact, and before rendering, run both checks:

```bash
Rscript check_reported_numbers.R
Rscript theory/check_manuscript_claims.R
```

The Check workflow (`../.github/workflows/check.yml`) runs both on every push and pull
request, with the three packages they load restored from `renv.lock`, so a mismatch also
fails the push's checks.

`check_reported_numbers.R` compares `preregistration.qmd` with the title and abstract limits
in `journal.json`, the 0.90 and 0.95 precision requirements, the ordinal refusal and
projection, the Scopus counts, and the theory object's rigour score and its construct,
proposition, auxiliary-assumption and rival counts. It exits 1 on a mismatch, and also when a
block cannot run, for instance when theoryforge is not installed, unless
`INTRACT_ALLOW_SKIP=1` is set. It does not read the supplement, and quoted numbers outside
that list are not checked. `check_manuscript_claims.R` does not read the manuscript either.
It prints the counts, scores and structure the theory object yields, for comparison with the
text by eye, and fails only if a prediction names a proposition or a rival account that does
not exist.

The quoted numbers come from these artefacts:

| What the protocol quotes | Artefact | Written by |
|---|---|---|
| Distinct texts and children needed at 0.90 (Table 1, Design and precision analysis) | `design_analysis/minimum_texts.csv`, columns `value`, `lo`, `hi` | `run_design_analysis.R` |
| The same at 0.95 | `design_analysis/minimum_texts_095.csv` | `solve_at_095.R` |
| The Bayes-factor requirements, quoted to the nearest ten (Table 1, Design and precision analysis) | `design_analysis/minimum_texts_bf10.csv`, column `value` | `solve_at_bf10.R` |
| The ordinal refusal and projected text counts (Hypothesis 5) | `design_analysis/minimum_texts_ordinal.csv`, columns `note`, `projected_texts`, `projected_qualifying_texts` | `summarise_ordinal.R` |

| Rigour score, checklist and implications | `theory/tf_check.txt` | `build_theory.R` |

| Figures 1, 2 and 3 | `literature/scopus_gap_intersections.pdf`, `figures/nomological_net.pdf`, `figures/fig_precision.pdf` | `replot_scopus_figures.R`, `make_nomological_net.R`, `make_precision_figure.R` |

## theory/

The constructs, causal propositions, auxiliary assumptions, registered rival accounts and
confirmatory predictions, held as one machine-checkable file.

| File | What it is |
|---|---|
| `intract.theory.yaml` | The theory object. The source of truth for every hypothesis. |
| `build_theory.R` | Validates it, scores it against the rigour checklist, screens the constructs for redundancy and derives the graph's testable implications. Writes `tf_check.txt` (which includes the implications), `tf_severity.csv`, `tf_redundancy.csv` and `intract_nomological_net.svg`. Exits with an error if the object fails validation or the checklist's gate, or if its graph is cyclic, after writing the report that says why. |
| `intract_nomological_net.svg` | theoryforge's default rendering of the net. The manuscript does not use it, and Figure 2 comes from `make_nomological_net.R`. |
| `report_theory.R` | A console summary of the score, the checklist and the implications. Writes nothing. |
| `check_manuscript_claims.R` | Prints the counts, scores and structure the object yields, for comparison with the manuscript by eye, and fails if a prediction names a proposition or a rival that does not exist. |
| `diagram_theory.R` | Prints the class, names and structure of what `tf_diagram()` returns. No other script or document uses it. |
| `make_nomological_net.R` | Emits the nomological net (Figure 2) from the theory object, restyles the layout without touching its content (a hard assertion compares the node and edge sets), and renders the SVG, PDF and PNG. The manuscript embeds the PDF. Before writing the figure, it stops if the smallest type would print below six point at the protocol's embedding width, and reports any colour below the contrast floors the other figures are held to. The layout comes from the viz.js engine bundled with DiagrammeR, so a system Graphviz can lay the `.gv` files out differently. |

The object currently scores 90.7 out of 100 with no blocking failure (`tf_check.txt` always
holds the current figure), and its causal graph is acyclic, which is what lets
`tf_implications()` derive the thirty independence claims, three of which the fourth
outcome-neutral quality check tests. `tf_check()` scores the object alone and never reads the
manuscript. `check_reported_numbers.R` compares the score and the counts with the protocol,
but nothing compares the wording of a prediction, so a change to a hypothesis's rule in the
manuscript still has to be copied into the prediction statement by hand.

## design_analysis/

The precision analysis, built on portable design specifications.

| File | What it is |
|---|---|
| `tier1_developmental.json` | Tier 1, the text effects and their moderation by age band. |
| `tier1_narration.json` | Tier 1, the narration selectivity contrast. |
| `tier1_reported_difficulty.json` | Tier 1, the ordinal model of the child's own difficulty rating. |
| `tier2_within_child.json` | Tier 2, accumulated reading within a child. |
| `helpers.R` | The functions the design-analysis scripts share, sourced by each: the curve solver, the Wilson interval, the readers of the settings below, the cache keys and the session records. |
| `run_design_analysis.R` | Runs five sweeps: distinct texts, readings per text and a null condition for the developmental model, distinct texts for the narration model, and children for tier 2. Writes `precision_sweep.csv`, solves the texts, narration and children curves for the number needed to reach a determinate verdict nine times in ten, and writes `minimum_texts.csv` and `session_info.txt`. |
| `solve_at_095.R` | Re-solves the cached curves at 0.95 assurance, the floor Nature Human Behaviour names for frequentist plans, without re-simulating anything. Writes `minimum_texts_095.csv`. The protocol registers 0.90 and reports these figures beside it. |
| `solve_at_bf10.R` | Prices the Bayes-factor criterion for a non-negligible verdict (interval Bayes factor of at least 10 under the reference prior) from the cached curves by a normal approximation: each grid point's mean interval width gives its standard error, the probability that a 0.10 effect clears the criterion is `pnorm(0.05/SE - z*)`, and the same solver inverts the curve at 0.90 and 0.95. Writes `minimum_texts_bf10.csv` (with `value_at_196`, the same approximation at the simulation's own criterion, for comparison) and `sweeps/bf10_calibration.csv`, the approximation against the simulated probability at every grid point. The re-run at the observed inputs computes the criterion by simulation and supersedes these figures. |
| `run_ordinal_analysis.R` | The same question for the ordinal outcome behind Hypothesis 5. The general routine fits a linear mixed model, which would answer a different question about a three-category response, so pilotr still generates the data and `ordinal::clmm` fits the cumulative logit the protocol specifies. Writes each grid point to `sweeps/` and `session_info_ordinal.txt`, then runs `summarise_ordinal.R`. |
| `run_variance_sensitivity.R` | Re-derives the tier-1 requirements with the share of variance between texts at 5, 13 and 20 per cent, under the simulation's criterion and the Bayes-factor criterion, and reads the registered 9 per cent rows from the cached sweeps (Supplementary Section S5). Writes `variance_sensitivity.csv` and `session_info_variance_sensitivity.txt`. |
| `session_info_variance_sensitivity_arc.txt` | The session record of the University of Oxford cluster run that simulated the 20 per cent sweeps, where a re-run of both 5 per cent sweeps reproduced the local ones. |
| `summarise_ordinal.R` | Pools the cached ordinal grid points, attempts the 0.90 solve, and projects the requirement from the fitted width scaling where the target lies beyond the simulated range. The projection starts from the coefficient as attenuated by the omitted child intercept, computed analytically and checked against the mean fitted estimates. Writes `sweeps/ordinal_texts.csv` and `minimum_texts_ordinal.csv`. `run_ordinal_analysis.R` runs it at the end. |

Each sweep and each ordinal grid point is cached under `design_analysis/sweeps/` as soon as it
finishes and is skipped on a later run, so a long run can be resumed. A key file beside each,
`<name>.key.json`, records the settings that produced it: the specification, the grid, the
focal effects, the formula, the region of practical equivalence and the replicate count, and
for an ordinal grid point the rating rate and the minimum number of raters. A run whose settings
differ from a cached file's key stops and names the file, and a cached file with no key stops
the run unless `INTRACT_ADOPT_CACHE=1` declares it produced with the current settings, in which
case its key is recorded. Package versions are not part of the key, and the session records give
them. The key does not cover the tier-2 preparation code, so delete `sweeps/t2_children.csv`
and its key after changing it. A session record is written only by a run that computed
something, so a run that reads everything from cache leaves the record of the run that produced
the results. Deleting the whole directory also discards the ordinal grid points, which are far
slower to regenerate than the rest.

A curve that reaches the target at no grid point is reported as not reached within the grid. A
curve that reaches it but cannot be solved, as happens with too few replicates per point, is
reported as not determined, with pilotr's reason, and the script warns. A setting that is not a
whole number, or not a number where a share is asked for, stops the script with its name.

| Variable | Default | Read by | Effect |
|---|---|---|---|
| `INTRACT_N_SIMS` | 200 | `run_design_analysis.R`, `run_variance_sensitivity.R` | Replicates for the developmental and narration texts sweeps. |
| `INTRACT_N_SIMS_2` | 120 | `run_design_analysis.R` | Replicates for the readings, null and tier-2 sweeps. |
| `INTRACT_WORKERS` | 6 | the three simulation scripts | Worker processes. Each script falls back to serial if its first cluster will not start. |
| `INTRACT_ORD_SIMS` | 60 | `run_ordinal_analysis.R` | Replicates per ordinal grid point. |
| `INTRACT_ORD_TEXTS` | `200,400,800,1600` | `run_ordinal_analysis.R` | The ordinal grid, comma-separated. |
| `INTRACT_RATED_RATE` | 0.30 | `run_ordinal_analysis.R` | The share of readings carrying a rating, rounded from the 10 of 35 rated sessions in the structural sample. |
| `INTRACT_SHARES` | `0.05,0.13,0.20` | `run_variance_sensitivity.R` | The shares of variance between texts to sweep, comma-separated. Shares already cached are read, not re-simulated. |
| `INTRACT_ADOPT_CACHE` | unset | the three simulation scripts | Set to 1 to accept a cached file that has no key file as produced with the current settings, and record its key. |
| `INTRACT_ALLOW_SKIP` | unset | `check_reported_numbers.R` | Set to 1 to let a check with skipped blocks exit 0. |
| `SCOPUS_API_KEY` | unset | `scopus_gap_analysis.R`, through scopusflow | The Scopus API key. |

The deposited specifications are not simulated exactly as written. Each sweep sets every
coefficient to 0.10 in absolute size, keeping the specification's sign (the null sweep sets
them to zero), sets the tier-2 accumulated-reading coefficient to -0.10, and replaces the units
at every grid point. pilotr crosses a within-child factor with every text a child reads, so the
tier-2 sweep keeps one randomly ordered reading of each of a child's five texts before fitting,
which leaves five rows per child on five distinct texts as the protocol registers. pilotr derives
the replicate seeds from each specification's own seed, so the grid points of a sweep, and the
alternative, null and readings sweeps of the developmental model, reuse the same replicate seeds.
The ordinal script sets its own seed for each replicate and overrides the specification's, keeps
replicates whose text variance is estimated at zero by refitting them without the text term, and
counts any replicate it skips.

The specifications are the reason the analysis code can be written and exercised before the
real data exist. `pilotr::simulate_design()` generates a dataset in the shape a specification
describes, and every analysis script will be run against it before the real data are
transferred, as the Code availability statement commits.


## count_script/

| File | What it is |
|---|---|
| `lets_story_summary.py` | The integrity check, script version 2026-09-17, sent to the data controller on 18 September 2026, standard library only. Reads nineteen columns besides reading time (identifiers, categories, the session timestamp and page counts) and treats reading time only as a column whose usability is checked, in bands ten times wider than one another, never crossed with any other field. Writes the summary data set and the manifest page. |
| `lets_story_summary_2026-08-05.py` | The version supplied to the data controller on 7 August 2026, kept byte for byte (SHA-256 09316DCC...B29B7A) because it produced the output Supplementary Section S8 tabulates. |
| `HOW_TO_RUN.md` | The instruction sheet sent on 7 August 2026, kept as sent. |

The 2026-08-05 version was tested on 17 September 2026 against malformed inputs, having been
correct on the sample and on clean synthetic exports. Five inputs unlike the sample made it
report a confident wrong figure: a part without a header row (its first data row, reading time
included, became that file's column names in the deliverable), identifiers in scientific
notation (300,000 accounts counted as 258,697, silently), a part without the reading-time column
(verdict "All 2,161 sessions carry a usable number" for 4,322 sessions), one unclosed quote (199
of 4,233 rows read, one row reported skipped, exit status 0) and an empty `story_id` (counted as
zero empty identifiers, the story title standing in for the identifier). Version 2026-09-17
refuses the first and fourth, and counts and reports the rest. It also reads some inputs differently. Among other changes, an empty
`story_id` is no longer replaced by the story title, and tokens such as `None` and `NaN` are
read as missing. On the sample, it reproduces every figure the earlier version reported,
adding seventeen rows of its own. The test scenarios are in `count_script/tests/`, and the
Check workflow compares their outcomes with the recorded ones on every push. Both versions
and the instruction sheet are listed in `../tools/frozen.txt`, so a commit that changes one
is refused.

The instruction sheet was deliberately not reissued, to keep the change to the data controller as
small as one file. Everything in it still holds of the new version: the command, the inputs it
accepts, the two files to send back, what the summary contains, the treatment of reading time and
the nineteen columns, and the timing (25.8 seconds against 27.0 for 259,280 rows). Two of its
sentences are now stale and are recorded here rather than corrected there: it says two counts
record rows set aside, where the new version has three, and it says the two outputs are "a few
tens of kilobytes", which was already wrong for the earlier version, whose manifest for the
35-row sample is 99 KB.

The data controller exports a single CSV, so the split-export failures cannot arise, and the
covering email asks for nothing about how the export is produced. It carries one note instead,
about the only failure that has actually occurred with this data. In the 35-row sample `user_id`
is written `4.89448E+18`, six significant digits, which is what a spreadsheet makes of a
nineteen-digit integer and is not what a warehouse writing a float produces, that being seventeen
digits and no plus sign. The file also has CRLF line endings throughout. It reached us in that
state: the copy in Downloads was created at 13:10:05 on 29 July 2026 and last written three
seconds later, so it was not opened and re-saved at our end. Where in the data controller's chain
the rounding happened is not established, and a sample of 35 rows may well have been prepared by
a different route than the export itself. Everything else in the file points to a clean export:
timestamps reading `2026-07-24 12:34:56 UTC`, `user_country` correctly quoted where the value
holds a comma ("Korea, Republic of"), and all 35 rows parsing to exactly 30 fields. The email
therefore describes the mechanism without attributing it, asks that the script be run on the CSV
straight from the export, and leaves the new version to print a warning if it meets rounded
identifiers.

The output of the 2026-08-05 version on the 35-row sample is deposited with the sample, not
here, and Supplementary Section S8 tabulates it. Re-running that version on the sample
reproduces every line of that output except the run date in the "summary produced on" row
(checked on 4 September 2026, again during the 12 to 13 September 2026 code audit, and again on
17 September 2026). The text the script writes describes the counts as too coarse to bear on
"either hypothesis", wording from when the protocol had two hypotheses. The statement applies
equally to all six.

| `publish_story_texts.py` | Writes `data/` from the extraction's tables, one compressed table per language, and with `--check` confirms that `data/` matches its manifest and the extraction record. Standard library only. |

The data controller delivered the texts on 1 October 2026 as StoryReview, a browser viewer that
shows one story at a time. Its data files are JSON wrapped in a JavaScript call, so the
extraction script removes the wrapper and reads every text directly, in about a minute. The
delivery is kept in `Oxford-40k-stories/`, which the root `.gitignore` excludes, because it
holds the data controller's viewer software as well as the texts. The extraction writes into
`Oxford-40k-stories/extracted/` by default, and the publishing script reads from there.

```bash
python story_texts/extract_story_texts.py
python story_texts/publish_story_texts.py
```

Before writing anything, the extraction script checks that every chunk file the index declares is
present, that the index and the texts correspond one to one, and that its own page and word
counts reproduce the viewer's. It stops with exit status 1 on any failure. Texts whose page
markers skip or repeat a number, or that contain an empty page, are listed in `anomalies.csv`
and kept, because they may be what the app served.

The delivery of 1 October 2026 holds 40,559 texts, all in US English. 40,500 are generated:
every combination of 10 heroes, 10 worlds, 5 themes, 3 plot types and 9 sidekicks, each in a
young, a mid and an old version. The other 59 are public-domain classics, mostly in a young and
an old version. The script lists 16 of the texts as unusual.

Before writing, the publishing script confirms that rewriting the extraction's table row by row
reproduces it byte for byte, so each language's table holds its rows exactly as extracted. The
pages table is not published, because it holds the same texts split at their page markers,
which `split_pages()` in the extraction script reproduces. The published record leaves out one
field of the extraction's, the data controller's path to the folder it built the viewer from.
A delivery is expected to hold every language, English included, since the record and the
list of unusual texts describe a single extraction. The Check workflow runs
`publish_story_texts.py --check` on every push.
