# InTRACt Stage 1 Registered Report

`preregistration.qmd` is the protocol. `supplementary.qmd` is the supplementary material.
Both render to PDF and HTML with Quarto and cite `InTRACt references.bib` in Nature style
through `nature.csl`.

```bash
quarto render preregistration.qmd
```

Everything the protocol asserts about itself is generated by one of the scripts below, so a
claim in the manuscript and the artefact behind it cannot drift apart. Run each from this
directory.

## theory/

The constructs, causal propositions, auxiliary assumptions, registered rival accounts and
confirmatory predictions, held as one machine-checkable file.

| File | What it is |
|---|---|
| `intract.theory.yaml` | The theory object. The source of truth for every hypothesis. |
| `build_theory.R` | Validates it, scores it against the rigour checklist, screens the constructs for redundancy and derives the graph's testable implications. Writes `tf_check.txt`, `tf_severity.csv`, `tf_redundancy.csv`. |
| `report_theory.R` | A short console summary of the same. |
| `check_manuscript_claims.R` | Prints every number the manuscript quotes about the theory beside the number the object actually yields, and fails if a prediction names a proposition or a rival that does not exist. |
| `make_figure1.R` | Emits the nomological net as Graphviz source and SVG. |
| `render_figure1.R` | Renders that to the PNG and PDF the manuscript includes. |

Editing a hypothesis in the manuscript without editing it here will make `tf_check` fail,
which is the point. The object currently scores 90.9 out of 100 with no blocking failure,
and its causal graph is acyclic, which is what lets `tf_implications()` derive the thirty
independence claims that four of the outcome-neutral quality checks test.

## design_analysis/

The precision analysis, built on portable design specifications rather than on prose.

| File | What it is |
|---|---|
| `tier1_developmental.json` | Tier 1, the text effects and their moderation by age band. |
| `tier1_narration.json` | Tier 1, the narration selectivity contrast. |
| `tier1_reported_difficulty.json` | Tier 1, the ordinal model of the child's own difficulty rating. |
| `tier2_within_child.json` | Tier 2, accumulated reading within a child. |
| `run_design_analysis.R` | Sweeps the number of distinct texts and, separately, readings per text, and solves each curve for the number needed to reach a determinate verdict nine times in ten. |
| `run_ordinal_analysis.R` | The same question for the ordinal outcome behind Hypothesis 5. The general routine fits a linear mixed model, which would answer a different question about a three-category response, so pilotr still generates the data and `ordinal::clmm` fits the cumulative logit the protocol specifies. |

```bash
Rscript design_analysis/run_design_analysis.R
```

Each sweep is cached under `design_analysis/sweeps/` as soon as it finishes and is skipped on
a later run, so a long run can be resumed. Delete that directory to force a rerun. Two
environment variables control cost: `INTRACT_N_SIMS` (default 200) and `INTRACT_WORKERS`
(default 6, falling back to serial if the worker cluster will not start). The ordinal script
takes `INTRACT_ORD_SIMS` and `INTRACT_ORD_TEXTS` instead, and is far slower: a cumulative logit
with a text-level random intercept costs much more per fit than the linear model does.

The specifications are the reason the analysis code can be written and exercised before the
real data exist: `pilotr::simulate_design()` generates a dataset of exactly the planned shape,
and every analysis script is run against it first.

## figures/

| File | What it is |
|---|---|
| `fig1_nomological_net.{gv,svg,png,pdf}` | Figure 2 of the manuscript, generated from the theory object. |
| `make_precision_figure.R` | Builds Figure 3 from `design_analysis/precision_sweep.csv`, and the supplementary narration and within-child panels. |
| `fig_precision.{png,pdf}` | Figure 3. |

`make_precision_figure.R` runs `depictr::check_figure()` before saving, which checks colour
separation for a reader who cannot distinguish two of the hues and refuses text below six
point at the column width the journal renders at.

## literature/

| File | What it is |
|---|---|
| `scopus_gap_analysis.R` | Sizes three concept sets and every intersection of them on Scopus, and compares publication trends over 2018 to 2026. |
| `scopus_gap_sizes.csv`, `scopus_topic_trends.csv` | The counts. |
| `scopus_search_record.md` | The dated record: every query verbatim, the field tag, the year limit and the package version. |
| `scopus_gap_intersections.png`, `scopus_topic_trends.png` | Figure 1 of the manuscript, and a supplementary figure. |

```bash
Rscript --no-save --no-restore literature/scopus_gap_analysis.R
```

Not `--vanilla`: the Scopus API key is read from `~/.Renviron`. Only count queries are issued,
one request per cell, so the cost is a few dozen requests and nothing is downloaded.

## Packages

Four packages carry the reproducible parts of this protocol, each archived with a DOI:
[theoryforge](https://doi.org/10.5281/zenodo.21229964) for the theory object and its scoring,
[pilotr](https://doi.org/10.5281/zenodo.21266313) for the design specifications and the
precision analysis, [scopusflow](https://doi.org/10.5281/zenodo.21252669) for the literature
sizing, and [depictr](https://doi.org/10.5281/zenodo.21266308) for the figures.

## Data

The session-level extract is not in this repository and is not in the research team's
possession. It is held by the data controller and is released only on written confirmation of
in-principle acceptance, under the sequestration arrangement the manuscript describes. What
this repository does hold is the protocol, the theory object, the design specifications, the
literature sizing, the provider-computed aggregate counts and the file manifest, none of which
contains a record of any individual.
